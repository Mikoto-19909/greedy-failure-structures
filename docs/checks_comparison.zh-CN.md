# 默认检查加速验收

本机三对交替测量中，默认检查中位耗时从 **147.79 秒** 降至 **78.89 秒**，
减少 **68.90 秒（46.62%）**，达到至少降低 40% 的约定目标。
这里比较完整 unittest＋mypy 与核心（包含必需研究验证）＋mypy，
不是算法加速、完整套件加速或远端 CI 等待时间改善的证明。

## 方法与结果

研究基线为 `21da85275c1db5f8cdd20ffa6fff4f8e75dd73c2`，已包含通过 PR #47/#48
合入的 R1/R1c；计时候选为 `47aad10`。两侧研究源码、配置、数据和 pyproject 相同。
两侧使用同一个 Python 3.12.14 解释器、NumPy 2.3.5、SciPy 1.18.1、mypy 2.3.0、
Matplotlib 3.11.1。R1c 会话确认计算及独立复核进程已结束；计时期间本任务未并行
运行其他本地重检查。先各暖机一次，再串行执行三对，顺序为新/旧、旧/新、新/旧。

| 正式配对 | 旧默认检查（秒） | 新默认检查（秒） |
| --- | ---: | ---: |
| 1 | 147.5331 | 78.8856 |
| 2 | 148.0464 | 79.2136 |
| 3 | 147.7858 | 78.7021 |

分别计算三次耗时中位数后，用 `1 − 新中位数/旧中位数` 计算降低比例。
原始时间、环境和全部日志见 [归档](../experiments/checks_comparison_v1/)，
其中两行 warmup 不计入中位数。每个计时覆盖 Python 进程启动、测试和 mypy；
任一步非零退出会终止测量，不写入该次成功计时行或最终完成汇总。

旧流程每次 419 项（418 通过，1 项可选 OR-Tools 跳过）；新默认流程每次 372 项
（371 通过，同一项跳过）。必需研究验证没有跳过，六次 mypy 均检查 38 个源码文件成功。
两项冗余测试被删除；59 项明确登记的场景保留在扩展层，新测试默认进入核心。
补足分层、冻结工具和独立验证的回归后，完整套件为 431 项，另行完整运行通过。

## 独立复核与范围

独立代理已核对三对 CSV、六份正式日志和环境记录，重算中位数、减少秒数及阈值，
与汇总一致。另两类复核实际测试了缺失/跳过研究验证不能通过、新增方法默认进入核心，
以及冻结工具对有效数据、损坏输入、上传失败、重试和远端读回的行为。
R1c 的 14 项研究测试与 2 项报告路径测试均保留并接入必需研究检查。

这是单机、暖缓存、三对成功执行的比较；不能外推到其他机器、冷启动或任何研究任务。
`results/checks-timing-v1` 的旧暖机数据因与研究计算并行而作废，不参与此次验收。
研究数学定义未更改；代理复核不等于外部领域专家审稿。

## 复现

在安装 [检查依赖](checks_and_evidence.zh-CN.md) 后，从含基线 Git 对象的仓库运行：

```console
python scripts/measure_checks.py --baseline 21da85275c1db5f8cdd20ffa6fff4f8e75dd73c2 --pairs 3 --output results/checks-timing-reproduction
```

输出目录必须尚不存在。基线由 Git 导出到该目录，当前工作树为新流程；两侧使用
同一解释器。应在固定候选代码、无其他研究计算的条件下复测，不覆盖旧测量记录。
