# Fault-injection matrix: publication gates

Companion to `tests/test_fault_injection.py`. Every cell below states what one
of the publication gates actually did when a benchmark artifact was mutated,
on a copy of one real `quick` run. The cases were derived from the declared
contracts and then executed; a cell is never filled from reading the checker
alone.

Scope: `configs/quick.json` (run with one worker), artifacts under
`results/_fixture_quick` (gitignored), regenerated by `_benchmark_fixture()`.
Where a gate passed a mutation it was not designed to catch, the cell says so
and names the measured mechanism; that is a blind spot, not an endorsement.

## The three gates

1. The validator (`.github/scripts/validate_benchmark_output.py`) recomputes
   every derived artifact from `raw_results.csv`, `instances.csv` and the
   execution plan, so a fault survives a correctly refreshed manifest checksum.
2. The manifest (`manifest.json`) records byte counts and digests per artifact;
   it proves a file was not altered after the run, and nothing more.
3. The content boundary (`.github/scripts/check_content_boundary.py`) runs in
   `evidence_backed_claims` mode. It permits quantitative prose while continuing
   to reject sensitive content and broken links in tracked files. The retained
   strict mode rejects quantitative claims when selected explicitly. Neither
   mode scans benchmark artifacts under `results/`, and claim-to-evidence
   mapping is reviewed through `experiments/core_rq/CLAIMS.md`.

|---|---|---|---|---|
| coverage value tampered | detected | detected when record stale; not detected after refresh | not applicable | single-file tamper is always detected; the unmeasured whole-tree case is a full consistent re-export, which is the validator's declared design boundary (consistency, not truth) |

| gap column tampered | detected | detected when record stale; not detected after refresh | not applicable | same as the coverage row; no single-file path was measured to pass |
| manifest checksum tampered | detected | detected (the record no longer matches the file) | not applicable | a refreshed record is silent by design; the checksum proves absence of post-run alteration only |
| seed field tampered | detected (raw rows); not detected (instance records, blind spot) | detected when record stale; not detected after refresh | not applicable | instance records are not re-derived from the plan; the seed flows into no derived artifact, so a fabricated instance seed changes nothing the validator compares |
| canonical row order shuffled | not detected (blind spot) | detected when record stale; not detected after refresh | not applicable | every recomputation keys on run_id or sorts by group key, so row order is outside the checked contract; the repository's determinism prose names reproducible ordering as a contract (see the open question below) |
| feasible-to-optimal disguise without certificate | detected | detected when record stale; not detected after refresh | not applicable | a status flip alone trips record validation; a fully consistent flip (status, coverage, gap, exact flag, bound) trips the derived-statistics recomputation; no single-file path was measured to pass |

## Measured evidence, row by row

Baseline: the unmutated fixture validates, so every rejection below is caused
by the mutation, not by a broken fixture.

1. coverage tampered: validator rejected with the recomputed gap disagreement.
2. selected tampered: validator accepted, on both a greedy row and an exact row
   (checksum refreshed). The only selected-vs-coverage replay in the validator
   requires a Lazy Greedy variant, which this configuration does not have.
3. gap tampered: validator rejected with the recomputed gap disagreement.
4. checksum tampered: validator rejected with a digest mismatch.
5. seed tampered: raw-row seed rejected against the execution plan; instance
   record seed accepted. Seed and run_id changed together were rejected at the
   plan-identity step.
6. row order reversed: validator accepted, for both `raw_results.csv` and
   `instances.csv`, with the checksum refreshed.
7. feasible to optimal: the status-only flip was rejected by the record
   contract (a heuristic row cannot claim an exact status); the fully
   consistent flip was rejected at the derived-statistics recomputation.
8. certificate injection: every form tried was rejected by the record
   contract (all-or-none field rule, stochastic-family prohibition, legacy
   constructed-instance prohibition, proof-kind consistency rule). A value
   that conflicts with the solver results never reached the normalization
   stage, because the record contract blocks it first.
9. conclusion without evidence: a fabricated quantitative sentence was
   accepted when appended after the checked section, and again when inserted
   as a second headline section; a value change inside the checked section was
   rejected, and renaming the checked heading was rejected as a missing
   section boundary. The same sentence in a tracked prose file was rejected by
   the strict claim mode and accepted by the active evidence-backed mode; an
   untracked `results/` artifact was not scanned in either mode.
