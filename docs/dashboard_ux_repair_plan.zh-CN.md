## 当前实现与已有工作

- `src/maxcover/dashboard_ui/app.js` 的 `loadResult` 已有请求序号检查，但失败分支只写错误，没有清除或回退旧展示；成功分支没有清理旧错误。应补足现有处理，不另建状态管理框架。
- `DashboardService.list_results` 列出所有合法名称目录，`get_result` 却要求至少存在 `summary.csv` 或 `raw_results.csv`。前端只在内存中保留结果选择；目前持久化的是语言。
- 回放文件来自 `benchmark.py::_write_replay_artifact`，只在算法 **TIMEOUT / ERROR** 时自动保存，不是所有“贪心未达最优”的实例。页面需要解释这一区别，不能为满足文案而扩大保存或实验范围。
- 名称规则为 `^[A-Za-z0-9][A-Za-z0-9._-]{0,80}$`。本次保留这个约束，补充前端验证与中文/英文提示。
- 报告摘要当前截取原始 Markdown，原文件接口返回 `text/markdown`；需要增加可读展示，同时保留原文件访问方式。
- 已发现 `../wt-development-closeout` 的 `codex/dashboard-result-fix` 分支（HEAD `f195973`）有未提交的 7 文件改动；检查时为 399 行新增、92 行删除，涉及 UI、服务、测试和 CLI 文档。它已包含目录过滤、成功时清错、空回放按钮处理和引导布局等候选修改，但没有在本轮运行或验收。此状态可能继续变化。

### 阶段 1：结果与错误状态一致（问题 1、2、3）

范围：`dashboard.py`、`dashboard_ui/app.js`，必要的状态提示与 `tests/test_dashboard.py`。

- [x] 沿用请求序号检查；开始切换时清除旧结果展示和过期错误，显示正在加载哪个结果。失败时保持明确的错误/空状态，不继续把旧图表放在新选择下面。
- [x] 光谱来源、元信息、图表、摘要和当前选择一同更新；关闭或清除属于旧结果的图表弹层。成功加载和新实验完成后移除旧错误。
- [x] 结果目录筛选与 `get_result` 的基本可读前提一致；保留仅有 raw CSV 或仅有 summary CSV 的支持，不把“无图表”当作非法结果。
- [x] 持久化最近成功加载的结果名。优先恢复当前会话/保存的有效选择；无保存选择时按结果产物更新时间选择最新候选，同时间按名称稳定排序。目录 mtime 不能冒充实验完成时间，必要时用现有产物的 mtime 并标注“结果文件更新时间”。
- [x] 保存的结果已不存在或不可读取时，明确提示并尝试下一可用结果；全部不可用则显示有下一步指引的空状态。不可因一个坏目录陷入持续加载或报错循环。

验收：有效 A → 无效 B → 有效 C；A/B 快速切换且响应逆序；刷新期间改变选择；成功后旧错误消失；整页刷新保留结果；已删除的保存选择、存储不可用、无结果、仅 raw、仅 summary 都有明确行为。名称、光谱、报告链接与表格必须属于同一个结果。

### 阶段 2：输入与回放有明确反馈（问题 4、5）

范围：`dashboard_ui/app.js`、`index.html`、相关样式；必要时补服务错误的稳定分类。

- [x] 名称字段旁展示字符、首字符和 1–81 字符限制；输入时验证，错误关联字段并可被辅助技术读取。非法输入不提交运行请求；修正后可正常启动。
- [x] 明确区分“本次未启动”和“上一次任务已完成”；保留有用的历史状态但不让它代表当前提交。
- [x] 当前结果的计数标为“已保存异常案例文件”，说明其对应运行超时/错误，不等于贪心差距案例数。空回放时禁用案例、算法及运行控件，提供原因。
- [x] 回放列表按当前结果显示，案例标识可区分不同 run；切换结果时清除旧回放输出。仅有回放文件、没有 CSV 的目录仍应能通过明确的“其他已保存案例”入口访问，避免目录过滤顺带丢失既有回放能力。
- [x] 有文件时显示匹配、不匹配、不可比较或执行错误；回放进行中禁用重复提交，结束后按实际可用状态恢复。

验收：中文名称、空白、非法首字符、超长输入和合法修正；无文件 → 有文件 → 无文件；两个结果各有不同案例；仅含回放文件的目录可到达。使用临时小实例验证一次真实回放和一个坏文件，不为制造异常运行大实验。中英文状态均能理解。

### 阶段 4：提供可读报告（问题 7）

范围：报告展示、对应样式和原文件链接；按最终渲染位置补必要的服务测试。

- [x] 完整报告显示为可读的标题、段落、列表和表格，保留查看/下载 Markdown 原文件的入口；默认在应用内阅读并可返回对应结果。
- [x] 摘要显示原报告已有的结论段落及其限制，不做半句截断，不补写实验结论。缺少适合摘要的结构时，给出可读报告入口，不伪造摘要。
- [x] 实施前核对仓库可复用的渲染设施，再选最小可维护方案；完整保留原文。正文语言与 UI 语言分开标识，本轮不翻译或重新生成科研报告。
- [x] HTML 与链接处理遵循现有本地应用边界；正文中的 HTML、脚本或危险链接不能直接变成可执行内容。若需要新增依赖，先记录具体依赖及维护成本，不顺带引入前端构建框架。

验收：真实报告的表格、代码片段、结论限制可读，原始内容可取得；长报告、缺失报告、载入失败、快速切换结果不显示错误归属的内容。验证包含 HTML/危险链接的临时文本只作为安全内容显示。仅改成“打开 Markdown”不算完成本阶段。
