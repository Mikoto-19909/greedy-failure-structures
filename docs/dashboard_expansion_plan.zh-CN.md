## 第二层范围

1. **专题研究接入**：读取 R2 预算扫描、R3 确认实验、R4 前缀/DUAL 保存表格与摘要；保留原统计单位和已保存区间。文件可读、生产完成、历史验证状态分别说明。完整数据下载与有限预览分开。
2. **反例与猜想实验**：表单调用现有 mine/refute 工具；保留结构前提、计算预算、停止状态及独立验证结果。查看原始/缩小实例或猜想反例，并下载可回放案例。
3. **运行中心**：本地持久任务记录、排队、日志、失败/中断状态和明确的重试/适用恢复。处理重启和重复服务，避免未知存活任务被重复执行。只接受明确的白名单任务和参数。
4. **研究输出**：保存比较选择、筛选条件、说明与当时的描述性汇总；导出完整筛选记录 CSV、摘要 Markdown 和 SVG 图。保存的分析与重新读取最新输入明确区分。

现有 benchmark、R1、R1c 的实验身份、种子、算法、CSV 契约和恢复语义保持原样。
专题页不重跑正式研究，跨实验页面不自动计算配对推断或显著性。
缩小反例仅保持原工具声明的性质，不自动宣称仍满足猜想前提。

## 分工与顺序

- 专题读取模块与其测试由一个写入者负责。
- 运行中心后端及测试由一个写入者负责。
- 新专题/反例/运行前端由一个写入者负责。
- 主代理负责现有入口与路由、研究输出、文档、整体验证和提交。

先约定 JSON 接口，然后集成页面。按功能模块保留可读源码；不引入通用插件框架、治理台账或新的实验 schema。

## 第三层：本地读取与管理

2026-09-20 按“继续下一步”推进第三层首版，基线 `05571c5`。本轮范围：

- 可重建的 SQLite 派生索引：缓存规范化记录、R1 原始轨迹和实验库元信息；按身份查单例，避免逐次解析整份 R1 文件。
- 有界的内存比较结果缓存；文件状态改变后失效。源 CSV/JSON 继续作为真源，索引错误时明确显示降级并直接读取。
- 本地索引状态与重建入口；已结束任务和保存分析可归档/还原。归档只写独立旁注，不改原记录、不移动或删除目录；活跃任务不可归档。
- 用固定的 100 来源/100,000 条人工记录比较新旧实验库、筛选、统计、分页、详情与完整导出，记录本机冷/热读取耗时；不运行科研批次。

硬验收是新旧输出一致、变化后不误用旧缓存、并发/损坏可恢复、归档可逆且不触碰原文件。性能以实测报告为准，不把人工夹具当作生产规模保证。上云和远程多人执行不列入当前计划。

### 第三层使用与取舍

打开 `/workbench` 的“本地数据索引与读取状态”可以查看本地缓存占用和降级原因，点击“重建数据索引”重新读取当前源文件。SQLite 保存在 `results/.dashboard_index/`，只保存派生读取结果；原始 CSV/JSON、任务和保存分析不会因重建改变。

普通源修改、删除、原子替换会使缓存失效。Windows 同文件等长改写并恢复 mtime 的情况通过文件 ChangeTime 检查，POSIX 使用 ctime；读取前后身份发生变化时重试或明确拒绝，避免返回混合版本。索引内部结构错误或数据库不可用时直接读取源文件，并在状态区保留诊断；重建可恢复可用索引。缓存不是科研独立验证或文件完整性证明。

“已保存分析”中可归档/还原；运行中心的已完成、失败、中断任务同样可操作。“包含已归档”控制列表显示。归档旁注保存在 `results/.dashboard_local/catalog.sqlite3`，原记录、冻结输入、结果和日志均不改写或挪动；活跃任务不能归档，损坏对象仍保留原来的错误提示。重建数据索引不清除这些旁注。

比较结果另外使用最多 32 项、总计约 8 MB 的进程内缓存，单项超过约 1 MB 不保留；完整导出始终保留全部匹配记录。比较仍最多选择四个来源，不改变指标、分母、排序或分页定义。

固定读取验收：从源码基线 `05571c5` 的兼容性 CSV 前十行构造 100 来源、每源 1,000 行，共 100,000 行人工记录。固定身份、种子和缺失参考规则写在 `scripts/benchmark_dashboard_index.py` 中。它们只测读取/界面数据处理，不是新研究样本；没有运行求解器。新旧完整实验库、4,000 行全量比较、14 个过滤/分页查询、2,000 行之后的记录、CSV 字节及 JSON 导出均一致，R1c 保存的 6,000 条轨迹及首末实例详情/导出也一致。

本机 Windows / Python 3.12.14 实测，热读各重复三次取中位数，未清空操作系统文件缓存：

- 100 来源实验库首次请求：旧版 4.217 秒，新版 8.265 秒，后者包含建索引。
- 同一实验库重复读取：4.175 秒 → 0.368 秒；新服务对象复用已有索引首次 0.375 秒。
- 四来源 4,000 行全量比较热读：0.180 秒 → 0.115 秒；重复查看第 20 页：0.182 秒 → 0.00467 秒。
- R1c 全量比较首次请求：0.448 秒 → 0.943 秒；热读：0.471 秒 → 0.172 秒。
- 人工 CSV 共 64,517,300 字节，派生索引额外占 238,747,648 字节（约输入的 3.70 倍）；29,801,326 字节的 R1c 副本额外占 50,483,200 字节索引。

这是以首次构建时间和额外磁盘换重复读取速度的结果，不是所有数据规模下的延迟承诺。可重复执行：

```powershell
& '..\wt-fast-verification\.venv\Scripts\python.exe' scripts/benchmark_dashboard_index.py --include-r1
```

本轮最终性能证据在 `output/verification/index-scale/run-ognez8ia/report-20260920T101659308101.json`，先行 `report.json` 保留但不作为最终结果。复用同一批人工输入可传 `--reuse-run output/verification/index-scale/run-ognez8ia --include-r1`；脚本不覆盖既有输入或报告，记录是否已有缓存。实验库首读包含索引构建时会更慢，且“新服务对象”计时不等同于独立进程重启测量。

### 本地使用

在当前项目运行 `python run_project.py dashboard`。同一回环服务提供两个入口：

- `/workbench`：实验库、比较、R1/R1c 轨迹、保存分析与研究输出。
- `/research`：R2–R4 专题、反例/猜想表单、持久运行中心。

本机独立工作树可复用既有解释器：

```powershell
Set-Location 'D:\test area\greedy-failure\wt-dashboard-workbench'
& '..\wt-fast-verification\.venv\Scripts\python.exe' run_project.py dashboard
```

**专题研究。** 页面按专题列出已有 CSV/JSON 和历史验证记录；表格完整扫描计数、预览前 200 行，下载保留完整原文。R3 主摘要以原图为统计单位，端点数单列；R4 的 G/U 作为近似比下界，不能把未认证直接称为失效。界面保留原 CSV 列名；JSON 中超出 JavaScript 精确整数范围的种子和候选计数以十进制字符串展示，下载原文件不变。

为便于本机立即查看，已在忽略目录 `results/research_views/` 放入四份展示副本：R2、R4、DUAL 复制自原工作树的既有产物；R3 表格和状态来自本地 Git 对象 `8663e0dcf576ab156535ff7403bb7e4715091357`。各目录 README 记录原来源，报告来自源码基线 `82353c0`。没有恢复大型 graphs，也没有重新运行或重新验证正式研究。这些文件不随代码提交；其他机器可按原专题使用指南恢复本地保存产物。

**反例与猜想。** 挖掘可选择 R1 文件或填写本项目单实例 JSON 路径。population 明确控制 pilot、fixture 或 all；缩小前后都展示实际集合与精确见证。猜想表单支持当前工具已有的等长、不重复、最大覆盖频数和比例阈值，并分别显示找到反例、有限域穷尽、预算耗尽。每个完成任务都经过原 CLI 的独立验证。

交互输入最多 4 MB、500 条实例；单实例 n≤256、m≤64，组合枚举最多 200,000、删减评估最多 10,000、入选最多 10 例。猜想搜索最多 10,000 个候选，维度沿用原工具 n≤12、m≤16。任务墙钟上限为 600 秒，包含验证耗时。完整 R1c 超过交互输入上限，须先导出单例或准备小批次。

**运行中心。** 队列只管理 mine/refute，两种任务串行执行。Benchmark 保留原入口与原检查点恢复，不受这条队列的串行限额约束。入队时保存输入和参数，输出使用唯一新目录；失败或中断后可按冻结输入新建任务，从头重跑。mine/refute 原工具没有检查点，界面不会将重试称为续跑，也没有暂停或取消功能。

任务记录、冻结输入、日志、结果保存在 `results/workbench_jobs/<id>/`。服务重启可继续读历史；若父服务异常退出但旧子进程仍在工作，新服务等待其执行锁，避免重复派发。真正中断的任务不会自动重跑。损坏记录原样保留并显示错误，不能作为已完成结果下载或重试。服务正常关闭停止派发，已启动的有界任务继续完成。

**研究输出。** 在比较页展开“保存此筛选与研究备注”，填写标题后保存。服务读取当前筛选的完整数据，保存当时的记录与汇总；随后下载不会重新读取源实验。CSV 导出全部匹配明细，Markdown 保留来源、分母、备注与限制，SVG 绘制全部有可用均值的分组，JSON 保留完整分析。没有可用均值时不提供空图。

保存文件位于 `results/dashboard_views/<id>.json`。“已保存分析与研究输出”可以重开旧摘要；“按当前文件重新比较”显式重新读取来源，结果可能变化。明细损失筛选始终不改变汇总分母；不同来源中的重复实例不变成额外独立样本。CSV 是规范化筛选记录，不替代原始 benchmark CSV。
