沿用 2026-09-10 审查准备研究及第一轮反馈；原研究材料保持原样。

## 范围与步骤

1. 实现 `python scripts/prepare_review.py --repo --base --head --output`。
   将版本固定为提交，以唯一 merge-base 比较候选；拒绝浅仓库和不确定历史。
2. 从 Git 对象生成 `review.md`、完整原始 `diff.patch` 和有上限的文本源码快照。
   静态定位 Python 定义、引用候选、测试 ID、依赖入口及前提文档。
   追踪本地导入时继续经过导出入口，并明确截断、未解析依赖及其他未核对项。
3. 使用合成 Git 仓库验证版本、路径、文件类型及失败行为，再生成原固定样例。
   不执行被审查仓库代码，不安装它的依赖，不恢复它的研究配置。

输出必须位于源仓库及其登记工作树之外，不能覆盖已有文件或目录。
不增加运行子命令、自动测试选择、通过判定、结果清单或校验和门禁。
静态引用和测试定义均为阅读候选，不证明覆盖充分、运行成功或验证器独立。

## 验收

合成用例覆盖无差异、无效版本、非直接父基线、无/多共同祖先、浅历史、
重命名、删除、二进制、链接、已有输出、源与其他工作树内输出、未提交编辑，
以及外部 diff/textconv 和模块导入副作用未触发。
核对原样例包的固定提交、变更规模、调用者、测试 ID、契约定义和证据边界。
运行相关工具测试和静态检查；合并前仍须按 CONTRIBUTING 完成检查及独立审阅。

## 发布前审阅修正

独立初审复现了两个问题：`diff.submodule=log` 会使 gitlink 变化退化为日志，
以及 `--repo` 指向子目录时差异与快照路径不一致（`diff.relative=true` 还会漏掉范围外变化）。
已将输入归一到工作树根目录或 bare 仓库，并固定整仓差异及标准 gitlink 补丁格式。
先确认新增回归测试在旧实现失败，再验证修正后全部 16 项工具测试和脚本类型检查通过。
保留原初审材料；最终复核和较完整检查的实际结果随 PR 说明提供。
