# 可视化实验设计器：首版设计稿

2026-09-23。状态：设计已成稿，平台功能尚未按本稿改动。

目标：用户从已有方案出发，在页面里修改数据组和算法，检查后保存为自己的实验，再交给已有运行中心执行。

配套的[页面线框](visual_experiment_designer_v1.html)可以直接用浏览器打开。线框（Wireframe）是展示页面结构和操作顺序的草图。它只演示交互，不读取实验数据，也不保存或运行实验。

## 先规定什么

首版先确定以下七件事。具体数值、颜色和控件尺寸留到实施时处理。

1. **实验范围**：首版能设计哪类实验，哪些配置继续使用原编辑器。
2. **页面流程**：用户从哪里进入，每一步要完成什么。
3. **可编辑内容**：哪些内容直接操作，哪些保留模板值。
4. **检查与报错**：什么时候允许保存，修改后哪些检查失效。
5. **保存规则**：模板、未保存修改和本地方案如何区分。
6. **运行交接**：设计器把什么交给运行中心，哪里才真正开始计算。
7. **验收标准**：用哪些用户操作判断首版可以交付。

本稿对这七项给出实施默认方案。实施者可以调整布局和代码组织，但应保留这里规定的操作行为。

## 范围：先完成一种完整操作

首版面向同一批数据上的算法比较，也支持在一个方案中放入多个数据组。
数据组（Case）是一套固定的实例生成规则。一个数据组经过多次重复，会产生多个具体实例。

首版提供这些操作：

- 从受支持的模板或本地方案复制。
- 为新实验命名。
- 增加、复制或删除数据组，修改其规模和结构参数。
- 勾选比较算法，查看可用的最优值参考算法。
- 设置重复次数，查看或修改随机种子。
- 查看本次改动和计划规模，检查后保存。
- 携带已保存方案进入运行中心，由用户单独提交运行。

首批表单覆盖两类数据组：均匀随机（`uniform`）和共核重叠（`high_overlap`）。前者让元素按给定概率进入集合。后者让部分元素更容易被多个集合共同包含。可以创建只含一组的方案，也可以保留两组对照。

首批算法表单覆盖贪心（`greedy`）、惰性贪心（`lazy_greedy`）和穷举（`brute_force`）。惰性贪心缓存部分收益计算。穷举检查候选组合，可以在完成精确求解时提供最优值。表单保留算法的现有选项和标识，不自动重命名它们。

其他算法、其他数据组类型、多参数扫描和随机算法的多组种子，继续由现有完整配置编辑器处理。参数扫描（Parameter sweep）指为参数列出多个值，再按这些组合生成实验。首版不增加扫描设计页面。

首版不增加拖拽连线、自动寻找实验参数、新算法或新的统计检验。它生成现有引擎已经接受的配置。

## 页面流程

入口放在现有配置管理页。主按钮叫“新建实验”；已有方案旁提供“复制后修改”。保留“完整配置编辑”入口。

```text
选择起点 → 编辑方案 → 检查并保存 → 到运行中心
               ↑           │
               └─ 返回修改 ┘
```

### 1. 选择起点

模板卡片展示用途、数据组类型和算法。点击卡片只选择起点；点击“复制并开始”才创建本地副本。

沿用现有复制行为：此时磁盘上已经有一份未修改的本地方案。页面应明确显示“副本已建立，当前修改尚未保存”。取消编辑不会自动删除副本。

只把全部内容能被首版表单表达的方案标为“支持表单编辑”。如果含不支持的内容，说明原因并进入原完整配置编辑器。不能偷偷删掉不支持的算法、选项或数据组。

默认展示小型探索模板。已有研究配置可以复制使用，但卡片应说明它的研究用途。不能把改过参数的副本称为原研究的复现。

### 2. 编辑方案

桌面布局分为主编辑区和右侧摘要。窄屏将摘要排在编辑区下面。所有操作都能通过键盘完成。

主编辑区依次展示四块内容：

- **实验名称**：用一句话说明这次想比较什么。
- **数据组**：每组一张可展开的条目。先显示组名、类型和规模，再展开结构参数。增加或复制一组后，用户可以直接修改；删除操作支持当页撤销。不同类型通过新增一组来替换，不在原条目内隐式转换参数。
- **算法比较**：勾选算法，分别说明它用于比较覆盖量、运行时间，还是提供最优值参考。既有模板选项先保留在折叠区。
- **重复与随机性**：重复次数单独展示。随机种子（Random seed）控制随机数据生成，用于重复实验；默认继承模板中的明确值。每次重新打开页面都不自动换种子。

右侧摘要回答三个问题：“比较哪几组数据？”“运行哪些算法？”“这些设置还需要检查吗？”

不把未检查的前端估算写成实际任务规模。首次进入显示“待检查”。检查后显示服务端给出的实例数与算法运行次数；再次编辑立即标为“已修改，需重新检查”。

具体控件原则：算法用勾选框，组类型用选择器，整数和概率用带解释的输入框。首版不需要为每个参数制作滑块。参数名称、范围和默认值以既有配置规则及模板为准。

### 3. 检查并保存

点击“检查方案”后，由现有服务检查当前完整配置。页面展示：

- 实际数据组数、实例数和算法运行次数。
- 相对已保存方案的改动。相对原模板的改动放在折叠区。
- 阻止保存的错误。定位到对应数据组或字段，并给出可采取的修改动作。
- 不阻止保存的说明，例如没有最优值参考，或精确算法可能无法在预算内完成。

只有当前内容检查通过，才能点击“保存方案”。保存完成后，再次读取保存结果，更新页面状态。

检查回答的是“能否按这些规则运行”。它不证明两组具有可比性，也不证明实验能支持因果解释。相同种子不自动构成有效配对；首版不新增“自动匹配对照”开关。

运行规模以现有计划器为准。多个算法处理同一个实例，不会增加独立实例数。首版不承诺预计完成时间；没有测量依据时只展示计划次数。

### 4. 到运行中心

保存成功后显示“已保存”，提供“继续编辑”和“到运行中心”两个动作。跳转时预选刚保存的方案，不能自动加入队列。

运行中心继续负责输出位置、执行资源、排队、暂停和续跑。用户点击现有提交按钮后，才建立任务并固定输入副本。

任务建立后再修改设计，不改变已经排队的任务。计算结果沿用现有实验库、报告和实例入口。设计器不另建一套结果页面。

## 保存与状态必须说清楚

使用同一份当前配置驱动表单和完整配置编辑器。表单对指定字段做修改，不能根据可见控件重建整份文件。

模板始终只读。本地方案通过现有保存服务写入 `configs/local/`。未保存修改只在当前页面保留；刷新或离开前给出提示。首版不新增浏览器自动备份或完整版本历史。

状态及按钮行为如下：

- **未修改**：可以查看已保存方案；复制后才进入模板编辑。
- **已修改，待检查**：允许继续编辑和检查；禁止保存及带着旧版本去运行。
- **检查失败**：保留全部输入；展示错误；允许修改后重试。
- **检查通过，待保存**：允许保存；任何编辑都会退回待检查状态。
- **正在保存**：禁止重复提交及继续编辑；等待保存结果。
- **已保存**：允许进入运行中心；继续编辑后重新检查。
- **保存冲突**：说明其他页面或文件已经修改了方案；保留当前输入；提供重新读取和复制当前文本。用户自己决定取舍，不静默覆盖。

检查、读取与保存出现连接错误时，保留当前输入。恢复连接后可以重试。较早请求返回的结果不能覆盖较晚的编辑。

从完整配置编辑切回表单时，重新检查是否全部受支持。如果不能无损表达，继续停留在完整配置模式。无损指字段、算法标识和种子值没有因切换模式而改变；缩进变化不算内容变化。

种子值按整数文本传递，交给后端解析。不能经过浏览器浮点数转换而改变大整数。已有配置格式版本不自动升级。

## 与现有代码怎样衔接

以下文件位置以较新主线为准。它们在本稿所在的旧工作目录中可能尚不存在。

- `src/maxcover/dashboard_ui/experiments.html`、`experiments.js`、`experiments.css`：承载设计页面、状态切换和字段操作。优先扩展现有页面。
- `src/maxcover/dashboard_experiments.py`：复用 `ExperimentsService` 的读取、复制、预览和保存方法。增加一层受支持字段的适配即可，不再建立另一套存储。
- `src/maxcover/config.py`：复用配置解析和规则检查。前端只做即时提示，服务端作最终判断。
- `src/maxcover/benchmark_planning.py` 及现有 `plan_benchmark` 入口：提供实际计划规模。不得在界面里重新实现任务展开算法。
- `src/maxcover/dashboard.py`：沿用现有路由和本机访问约束。新增操作只接到配置服务。
- `src/maxcover/dashboard_jobs.py` 与 `dashboard_ui/research.js`：接收已保存方案，继续使用现有队列和固定输入行为。

数据流保持为“页面修改 → 完整配置文本 → 现有检查服务 → 现有保存服务 → 运行中心”。可以给检查响应增加字段定位信息，但不为设计器修改实验结果格式。

实施前先验证一个技术点：现有基础参数适配只处理名称、种子和重复次数。算法与数据组的新适配也必须保留不可见字段和大整数。建议沿用服务端处理配置文本的方式，避免在浏览器中解析后丢失精度。

## 落地顺序与完成标准

### 第一步：接通一条最小流程

从含均匀随机数据组的现有方案复制。打通命名、修改重复次数、检查、保存、预选到运行中心。先验证保存与运行使用的是同一份内容，再扩展表单。

完成标准：整个过程无需手写配置；模板内容保持不变；跳转不启动计算；重新打开能读到刚保存的方案。

### 第二步：补齐首版编辑范围

加入两类数据组和三种算法的表单。补上数据组复制、删除撤销、差异预览、完整配置模式和状态失效处理。

完成标准：受支持方案可以往返于表单和文本而不改变配置语义；不支持方案不会丢字段；非法输入不能成为可运行的保存文件。

### 第三步：完成真实操作验收

先运行配置、平台服务和队列的相关既有测试。补充新字段适配和状态转换所需的行为测试，不编写只检查文档措辞的测试。

浏览器至少覆盖以下十项：

1. 从模板复制并修改，保存后重开；原模板内容不变。
2. 两类数据组可以增删与复制；删除可以撤销；组名重复会收到错误提示。
3. 算法选择与后端计划一致；取消全部算法不能通过检查。
4. 删除最优值参考算法后仍可比较覆盖量；页面明确说明不能据此计算最优差距。
5. 输入非法重复次数或选择数超过集合数量时阻止保存；改正后可以恢复。
6. 检查通过后继续修改，旧检查立即失效；慢请求不能恢复旧状态。
7. 两个页面编辑同一方案时出现保存冲突；当前输入仍在。
8. 大整数种子及不可见字段在切换编辑模式后保持；复杂配置进入完整配置模式。
9. 保存后的方案进入运行中心但不自动提交；以独立临时输出运行一个小型任务；提交后改方案不影响任务输入。
10. 检查连接错误、刷新前提示、键盘操作和窄屏布局；输入和操作按钮可用。

第九项只验证软件路径，不作为新研究结果。使用临时数据与临时输出，避免覆盖已有实验。另按项目要求执行日常检查；合并前安排独立复核，让复核者实际操作一个正常流程和一个非法输入。

可交付的首版应同时包含页面、服务适配、操作说明和上述验收结果。页面能打开并不等于设计器已完成。
