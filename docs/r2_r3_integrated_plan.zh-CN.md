## 1. 共同问题与已有依据

R2 回答：在独立定长集合模型中，预算与集合大小如何对应 Greedy 失效率和损失？
R3 的研究边界是：固定每个集合大小、每个元素覆盖频数，通过连接结构对照检验
由机制证据提出的解释。具体结构假设、操纵对象与比较方法待 R2 分析和可行性探测后确定。
两阶段可复用原图表示、预算评估和机制诊断；R3 确认样本与探索、探测样本分离。

已有研究的状态与依据见下列文档，无须为启动准备重复执行：

- **R1a/R1b 已完成：** [设计](../analysis/r1_prefix_exchange_design.md)和
  [探索报告](../analysis/r1_prefix_exchange_report.md)记录了离线工具、功能样例验证，
  以及原 pilot 全部 60 个实例的前缀、平局裁决和交换分析；这些是已有样本的探索性重分析。
- **R1c 已完成，方向尚未确认：** [专项设计](../analysis/r1c_confirmation_design.md)和
  [正式报告](../analysis/r1c_confirmation_report.md)记录了 3,000 对新样本及独立重算。
  主差值区间包含零、精度目标达到；辅助交换修复差异仅提供线索，不能单独归因于重叠。

这些工作提供可复用方法，不支持预设“重叠越高越容易失败”或 R3 必须出现某一方向。

### 阶段依赖与两个设计冻结点

前置依据为已完成的 R1a/R1b 机制分析及 R1c，提供前缀失效、平局裁决和交换修复的
分析方法与研究线索。但 R1 的已有结果不自动满足 R3 的启动条件；仍需结合 R2 模型下
的结构观测与具体轨迹，判断能否提出可检验的结构解释。

执行顺序为：

**核对 R1 依据 → R2 独立预检 → 冻结点 F2 → R2 探索与机制分析 →
R3 可行性探测 → 冻结点 F3 → R3 独立新样本确认。**

- **冻结点 F2：R2 正式探索样本生成前。** 完成独立的分布与资源预检后，固定生成分布、
  参数网格、样本量与种子、最优见证规则、指标及统计方法、机制诊断的抽样安排、缺失处理和停止规则。
  预检样本不并入正式探索样本。
- **冻结点 F3：R2 结果分析和 R3 可行性探测之后、R3 正式确认样本生成前。**
  根据 R2 分析及探测结果，固定结构假设、操纵对象、重连协议、对照与嵌套安排、
  主估计量、链长、样本量、统计方法和停止规则。探索与探测样本不并入确认样本。

两个冻结点均指研究设计与分析决定的定版，区别于后续证据文件的归档或发布。
冻结后如需实质调整，应明确记录原设计停止或修订及其原因，区分调整前后的样本用途，
不将调整后的分析追溯表述为原定方案；任何修订都不能把已见结果的样本重新称为独立确认。

### 第一轮范围

沿用[总研究计划](greedy_failure_research_plan.zh-CN.md)第 4、5 节的顺序与边界。
N 为元素数，M 为候选集合数，d 为每个集合的大小；第一轮只做 `M=N`、
`fixed_size(unique_sets=false)`、无生成器 `coupling_seed`。
每个集合内部无放回，集合之间允许重复；保留标签，平局裁决固定选择最低集合索引。
这对应 [Balkanski 等，Definition 1 与 §2](https://arxiv.org/html/2604.24884v1) 的基础模型。
其期望近似指标为 `E[G]/E[O]`，不能用 `E[G/O]` 替代。

定长与密度模型比较、纯 Bernoulli、双正则模型、改进 Greedy、R4 认证均留到后续。
特别是当前 `uniform_random` 会修补空集合，不能充当纯 Bernoulli 对照。

## 2. 共用的计算与数据

### 一个原图，多种预算

以有序集合系统 `A=(N,S_0,…,S_{M-1})` 为独立抽样单位，每张原图只生成一次。
R2 随后改变 k，重新构造预算实例而保留全集、集合内容和集合索引，生成种子不依赖 k。
R3 若比较同一变体的多个预算，也须显式保存和核对其来源；是否采用该安排及具体的
变体、预算嵌套结构在 F3 确定，不由当前共用计算建议提前固定。

现有 `_case_seed` 在没有 `seed_group` 时包含 case 索引；相同 `base_seed` 不保证同图。
现有 `instance_id` 包含 k，不更改该契约。专用离线数据增加 `base_graph_id` 作为
跨预算、跨变体的关联键，并逐项核对原图；键相同本身不证明图相同。

R2 对每个图评估标准 Greedy，以完整子集枚举作为穷举参考：
枚举 `2^M` 个索引子集，按子集大小直接维护各预算的最大覆盖及最优见证。
F2 固定见证契约：每个预算输出恰好 k 个不同集合索引，按升序排列；
多个最优解中取字典序最小者。生产器与独立验证器遵循同一契约，分别计算并比较见证。
该契约与现有 [`brute_force`](../src/maxcover/algorithms.py) 按升序组合枚举、仅在覆盖量
严格增加时替换见证的行为一致。
由于 `k≤M` 且添加集合不会降低覆盖量，任意至多 k 个集合的选择均可扩展到恰好 k 个，
故两种约束的最优值相同；实现直接维护各 k 的见证，无须另设补齐流程。
可用流式 DFS 维护当前并集，避免为每张图持久保存整个子集表。
公共算法实现与 benchmark 格式不因此改动。
R3 的精确最优参考可复用该能力，是否适合最终尺寸与分析任务须在可行性探测中核算。

独立验证器用直接集合并集和组合枚举核对每个预定 k 的 O、Greedy 决策及见证；
不调用生产枚举器、结构增量更新或主统计函数。资源估算必须计入完整独立重算。
R1 轨迹工具的复用先受其 `max_completions` 等上限约束，不能把未完成写成认证完成。

### 专用产物与恢复运行

R2 拟在 `analysis/` 添加小范围入口与辅助模块；以下名称是候选，不是现有命令：

- `r2_budget_grid.py`：原图生成、跨预算评估及 R2 汇总。
- R2 独立验证入口：逐图重算、跨预算完整性和统计复算，名称随实现确定。
- 共用代码仅限必要的输入组织与调度；验证器不得共享被验证的核心计算。

R2 批次目录保留设计输入、原图、运行状态、逐预算结果和汇总。最小数据包括原图编号、
N/M/d、有序集合、生成种子、k、原有实例身份、G/O、选集、参考状态、结构量和实际失败原因。
R3 只在探测需要时实现相应构造工具；正式入口、变体/链关联和输出字段随 F3 专项设计确定。
若采用重连，应保存足以独立重放的初始图、随机流和交换记录，明确构造计数与停止状态。

检查点以原图及明确的子任务为单位，父任务只有全部必需子任务和验证完成才完成。
恢复运行时核对设计、来源图与完成状态，只执行未完成任务。
汇总从保存的原始数据重建，不为重画图再执行算法。使用一个汇总写入者，避免多进程争写 CSV。
保持既有种子、CSV、恢复运行行为和公共接口。

### 随机流分离

分离 R2 预检、R2 正式探索、R3 可行性探测和 R3 确认的随机流；
重连、区间重采样和置换诊断如使用，也不消耗原图生成流。
R2 候选方案按 `(版本,阶段,N,d,重复号,用途)` 确定性派生种子，在 F2 配置中列出
实际种子和用途；R3 的抽样及随机流安排在探测后于 F3 确定。
各阶段检查与原 pilot/R1c 及其他阶段不重用。
候选参数单元之间也使用不同生成流；同一原图的全部 k 共享原图。
伪随机复现不构成数学独立性的实验性证明，统计覆盖依赖预定抽样模型。

## 3. R2：用小规模网格定位区域

### 原则、候选值与 F2 决定

- **已确定的原则：** 第一批采用独立定长模型、允许重复集合、同图跨预算；保留固定
  平局裁决、穷举参考和指标区别，探索样本与预检样本分开。这些是设计原则，不是执行结果。
- **待预检的候选：** 以下网格、重复数、预检数量、资源上限和统计安排用于准备定版，
  尚未通过分布与资源实测；已核对的样本计数和枚举规模只是候选方案的算术。
- **F2 必须填定：** 实际分布与参数网格、样本量及种子清单、最优见证规则、指标定义、
  统计方法、机制诊断范围、穷举参考预算、缺失处理、停止与恢复运行规则，以及输出位置和执行命令。

### 候选网格与成本

建议 `N=M∈{12,16,20}`，`d∈{2,3,4}`；每个 `(N,d)` 取 200 张独立原图。
目标 `λ=kd/N∈{0.25,0.5,0.75,1,1.5,2}`，令 `k=ceil(λN/d)`，限制到 `[1,M]`，
去重后加入 `k=1,M`。报告实际 k 和实际 λ；舍入后不宣称各档精确对齐。
`k=1` 与 `k=M` 是已知最优端点，另以 d=1 小夹具检查退化边界，不混入正式网格。

完整候选为 1,800 张原图、13,000 条预算记录。
仅生产完整枚举约需 670,924,800 个子集状态；此数不含验证、轨迹、结构统计与 I/O，
不能换算成未经实测的运行时间。单张 N=20 图为 1,048,576 个子集状态。

独立预检拟在每个 `(N,d)` 使用 8 张非正式原图。分布核对包括逐集合大小、允许重复的
生成策略、未注入 `coupling_seed`、跨预算原图与标签一致；有限样本频率不能证明抽样分布正确。
资源核对测生产、验证、机制诊断、最大内存与输出大小，记录典型值及最慢样本，给出全批估算。
候选资源上限为总墙钟 12 小时、最多 4 个工作进程、总内存 6 GiB、输出 2 GiB；
这些上限用于资源规划，实际耗时与容量须经预检核对。
预检只用于分布/正确性/资源决策，不按 Greedy 效果筛掉参数档。
若 N=20 超预算，可在 F2 前整档延后，首批保留 N=12/16，重复数不因已见效果改变；
F2 定版时重算全部数量。F2 后的实质调整按设计修订处理，不作为原方案内的自动缩档。

### 指标、图与不确定性

令 G 为标准 Greedy 选择的覆盖量，O 为穷举参考得到的精确最优覆盖量。
每个 `(N,d,k)` 对全部预定原图分别报告：

- 失效率 `p̂=mean(1[G<O])`，作为定位预算区域的首要描述量。
- `sum(G)/sum(O)`：对接文献的期望值之比。
- `mean(G/O)`：逐实例近似比的均值。
- `mean((O-G)/O)`：平均相对最优性差距；单个实例的相对最优性差距为 `(O-G)/O`，
  达到最优的实例以零值进入平均。
- 绝对损失 `O-G`、G 与 O 各自的分布、全部候选集合的并集大小 `|⋃ᵢ Sᵢ|`、
  元素频数、重复集合比例、交集集中度。

必须保留全部预定原图及参考状态。本批 d≥1、k≥1 应有 O>0；出现零最优值、
未证最优或缺失原图视为异常或未完成，不能静默剔除后宣称完整。
候选统计方案为失效率逐点 95% Clopper–Pearson 区间；200 原图仅适于较粗定位。
曲线若使用 bootstrap，按 `(N,d)` 内原图整体重采样并连带所有 k，候选为 10,000 次，
使用独立种子，明确它是近似、逐点的不确定性展示；是否使用及实际方法在 F2 写定。
不将逐点区间当同时置信带，不进行事后挑峰显著性检验。

交付失效率和平均相对最优性差距随实际 λ 的曲线与结构分布，说明整数舍入和有限尺寸效应。
观察到单调、非单调或没有清晰区域均是可接受结果；只称经验区域，不证明极限相变。
F2 应明确完成固定探索样本后的停止规则，不按已见效果扩样。资源中断保留原图和状态，
按冻结方案恢复运行；最终无法完成则报告缺失及限制，不能用补抽容易样本替换难图。

### R2 机制分析与 R3 触发依据

R2 在预算曲线之外结合结构观测开展 R1 式前缀、平局裁决与交换诊断。
机制诊断的候选抽样安排为每个 `(N,d)` 取重复号最小的 32 张原图，在可承担的预算位置分析；
具体预算、诊断范围及计算限额须在 F2 固定，不只挑失败图。
结果出现后为解释现象另选的案例单独标注，不并入预定概率估计，也不冒充独立确认。

结合已有 R1 分析与 R2 中独立重算的具体轨迹，提出明确的结构假设：哪些连接性质
可能影响 Greedy 的选择过程，哪些现象支持或限制该解释，固定两侧度序列如何帮助检验。
高失效率区域可帮助寻找案例，但本身不足以构成机制解释；进入探测也不要求统计显著。
不预设按失效率排序选点，不设失败数量门槛，不提前限定 R3 的参数单元、主预算或结构量。

只有形成可检验的结构解释后才进入 R3 可行性探测；否则交付 R2 结果及尚不能推进的原因。
R2 的完成不以找到 R3 假设为必要条件，相关性与选例也不当成因果证据。

## 4. R3：条件推进，具体设计待冻结

本节说明通用推进条件。本批条件探测与 F3 已完成，具体协议和参数以
[专项设计](../analysis/r3_confirmation_design.zh-CN.md)为准；不将该方案预设为其他批次的默认方法。

### 触发依据

结合 R1 方法、R2 结构观测和具体轨迹，提出可检验的结构假设，说明哪些连接性质
可能影响 Greedy 的选择，以及固定两侧度序列如何帮助检验。高失效率本身不足以支持机制，
进入探测也不要求先得到统计显著结果；当前不指定必须操纵的结构量或方法。

### 可行性探测

根据 R2 形成的结构假设，使用独立于 R2 正式样本的小规模输入，检查：

- 固定每个集合大小与每个元素频数后，是否存在非平凡交换空间。
- 目标结构是否能够实际改变，同时有哪些其他连接性质发生变化。
- 交换合法性、两侧度序列逐项不变和变体来源是否可以独立验证。
- 精确最优参考、机制诊断、构造和独立验证的总成本是否可承担。

探测前写明假设、输入来源、尝试方法和资源上限，保留方法调整与不可行情况。
探测用于检查构造与成本，不能因效应方向好看而推进；有限次未发现交换不证明不存在交换。

### 推进或退出

只有结构假设明确、操纵具备可行性且资源可承担时，才编写专项设计并进入 F3。
否则交付 R2 结果及停止理由；允许弃用或重新选择方法，不强行完成 R3。
C4、中性或定向重连仅是可弃用候选，不是默认方案、必需实现或验收条件。

### F3 待确定的设计项目

- 结构假设与依据、目标总体、参数单元、操纵对象及保持不变的量。
- 重连与接受/拒绝协议、对照、原图抽样、变体/链/预算嵌套、链长和随机流安排。
- 主估计量及分母、辅助量、样本量、统计方法、精度或功效目标和必要的多重比较处理。
- 精确最优参考与构造预算、缺失和不可行情形、停止与恢复运行规则、独立验证与执行命令。
- 适用拒绝条件对应的具体输入案例与预期行为；实现时纳入现有测试，不预定测试函数名，
  也不要求每类情况单独建立测试文件。

同一原图的多个变体、链或预算不能直接当作独立原图；确认样本与探索、探测样本分离。
固定两侧度序列不等于只改变一个结构因素，保度重连不能自动支持单独因果解释。
样本量和推断方案须针对最终问题核算；构造不可行、精确最优参考缺失、
方向未确认均如实报告，不能静默筛除或补抽替换，也不按已见效果改主量、挑链或增删样本。

## 5. 实施顺序与验收

**阶段 A：核对 R1 依据、R2 独立预检与 F2。** 先核对 R1 方法、已知结论及其限制。
实现 R2 所需的种子域、同图跨 k、流式穷举参考、原图级检查点和独立验证。
用 k=1/M、d=1、重复集合、多最优解及不同 O 的已知小例验证见证规则与指标。
例如 k=2 的有序集合 `({0,1},{1,2},{0,2})` 与 `({0,1},{0,2},{1,3})`，
采用低索引平局裁决时分别有 `(G,O)=(3,3),(3,4)`；汇总得到 `sum(G)/sum(O)=6/7`、
`mean(G/O)=7/8`、失效率 `1/2`、平均相对最优性差距 `1/8`，防止指标混用。
输出独立的分布与资源预检报告，完成 F2 中全部设计与分析决定，方可生成阶段 B 样本。

**阶段 B：R2 探索与机制分析。** 按 F2 执行网格、独立验证、描述曲线和轨迹诊断。
结合 R1 方法与 R2 结构观测，判断能否提出具体可检验的 R3 假设；没有形成假设也可完成 R2。
研究报告明确哪些是探索选择和追加选例，不将同一批图重新命名为确认样本。

**阶段 C：有条件的 R3 可行性探测与 F3。** 依据具体结构假设，开发探测所需的小范围工具，
以独立输入核对交换空间、实际结构变化、合法性、度序列与总成本。
按所尝试方法检查非法交换、无交换空间及未完成构造的处理，不要求实现全部候选思路。
满足推进条件后编写专项设计，独立复核所选方法并完成 F3；否则交付停止理由。

**阶段 D：F3 后的 R3 独立新样本确认。** 按专项设计实现并验证正式入口，再生成确认样本，
完成所选主量与独立重算，并实际执行 F3 定义的有效和无效输入案例。
新运行、中断后恢复运行、从保存结果重建汇总须给出一致研究结果；完整报告不支持假设的结果。

**阶段 E：联合报告与可选证据发布。** 先解释 R2 的模型、预算区域和机制观测。
若 R3 推进，再说明固定了哪些边际、实际结构对照及确认结果；否则报告条件未满足与停止理由。
各阶段说明推断范围及失败/未完成记录。
探索与确认数据分别标注并直接链接；不把机制干预结果外推为极限相变或唯一因果因素。
只有显式要求证据冻结/发布时，才按[检查与证据流程](checks_and_evidence.zh-CN.md)
选取必要文件并核对远端提交；源码提交不等于保存了忽略的实验结果。

### 分析文件登记与验证责任

新增 `analysis/` 下的 Python 文件（包括子目录文件）须逐文件登记到
[`scripts/check_profiles.py`](../scripts/check_profiles.py) 的 `ANALYSIS_OWNERS`，
键为相对 `analysis/` 的路径，使用 `/` 分隔。
新增非 `tool` 的研究 owner 时，同时配置 `RESEARCH_MODULES` 与 `REQUIRED_RESEARCH`：
测试模块须能被发现，必需场景至少两个且须存在于已发现的测试中，符合
[`scripts/check.py`](../scripts/check.py) 的现行检查。
归属已有研究的辅助文件复用该 owner，并补充受影响的验证，不为每个文件新建研究单元。

R2/R3 新增研究入口均须实际执行有效和无效输入验证，并由独立审查者核对受影响行为；
该责任不限于修改检查系统。验证器独立重算关键结果；登记至少两个场景是最低要求，
不能替代对验证内容充分性的判断，文件登记本身也不代表计算验证通过。
新测试默认核心，缺失或跳过必需验证不得当作通过。开发运行相关测试及 `python scripts/check.py`；
修改检查系统时，合并前另运行 `--profile full`。复用现有测试组织，不另建验证框架。
