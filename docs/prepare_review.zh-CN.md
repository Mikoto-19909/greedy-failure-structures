# 准备固定提交的审查材料

`scripts/prepare_review.py` 从本地 Git 提交生成静态审查包，便于定位差异、
未改动调用者、测试定义和执行前提。它不运行被审查仓库的代码，不给出通过意见。
未提交编辑、暂存区内容、忽略目录和远端状态均不纳入材料。

## 前提与命令

需要 Python 3.11 或更新版本、可执行的 Git，以及包含两个版本完整历史的本地仓库。
工具只使用 Python 标准库，无需安装目标项目。输出目录不能存在，父目录须已存在；
输出必须在源仓库、它的全部登记工作树和 Git 元数据目录之外。

在包含工具的工作树根目录执行，例如重现原 reference 拆分样例：

```console
python scripts/prepare_review.py --repo ../greedy-failure-structures --base 0d37e6f9924b4fca925dda792382af5d5d01c660 --head ad13f19f3b478d679fcc2deda77d98984215d75d --output ../review-reference-local
```

也可把 `--repo`、两个版本和输出换成另一处本地仓库与提交。路径含空格时加引号。
每次使用新的输出目录；工具没有覆盖选项。成功退出码为 0，并打印 `review.md` 的位置；
失败退出码为 1，错误写到标准错误。使用帮助用 `--help`。

请求基线和候选各解析一次。实际比较起点是它们唯一的 merge-base，报告同时显示三者。
基线不必是候选的直接父提交。相同提交产生空差异；没有或有多个共同祖先、无效版本、
浅仓库均明确失败。工具不会拉取历史或修改 Git 所有权配置。

## 如何阅读输出

- `review.md`：固定版本、按类型标注的差异、最大文件、定义位置、引用候选、
  静态测试 ID、已有检查入口及未核对事项。所有测试均未执行。
- `diff.patch`：从实际比较起点到候选的完整 Git 差异，保留二进制变化，禁用外部 diff/textconv。
- `snapshot/001.txt` 等：从 Git 对象直接读取的有限文本快照。
  报告给出原路径、base/head 标签和行号；base 标签指实际比较起点。
  编号文本文件避免创建目标源码中的链接、可执行文件、特殊路径和大小写冲突。

先读迁移前后的定义与旧导出，再查看未改动的引用候选以及契约定义。
符号候选来自顶层定义的 AST 差异；引用来自名称、属性、import 和精确字符串匹配。
字符串匹配可以找到 `getattr` 或符号列表中的兼容入口，也可能引入同名但不相关的候选。
它不构成调用图，不证明函数迁移等价或测试覆盖充分。

从列出的测试源码确认有效与非法输入场景、完整测试 ID、夹具和依赖后，
使用目标仓库已有的测试入口执行。测试列表还可能包含文件内无关测试，动态生成、
继承或特殊加载机制下的测试可能缺失；ID 是源码定位信息，不保证能直接加载。
准备工具不会调用 `check.py --list`，因为列出检查本身也可能导入代码。
完整研究检查的配置准备要求不能自动套用到每个定向测试。

验证器如果复用了改动的计算，只能提供有限一致性检查，须由审查者确认独立性。
文档中的“已通过”属于历史陈述；相应输入和原始日志未随本包验证。
`__module__`、pickle、动态导入和 monkey-patch 行为仍需单独审查。

## 提取范围与失败处理

最多扫描 500 个候选 Python 文件、8 MiB 源码；单个文本快照上限 512 KiB，
最多 80 份快照。优先改动文件和执行前提，再收录引用候选及至多三层本地导入。
沿导出入口继续读取叶子模块；未解析的非标准库导入、深度/数量截断、
无法解析的 Python、超大文件和二进制都会在报告中标注。
不提取 base 的完整依赖关系，不识别所有自定义包布局，也不复制整个源码树或研究结果目录。
这些上限只约束导航和快照；原始差异仍完整保存。

输出路径会在读取前及写入前解析并检查，也识别指向源工作树的链接或 Windows junction。
生成期间不要由其他程序替换输出路径或它的父目录。最终报告最后以重命名方式写入；
写入失败可能留下部分文件用于诊断，但没有完整的 `review.md`。保留该目录，换一个新目录重试。
若 Git 报告所有权不匹配，应在获授权的仓库所属账户下运行，不要关闭全局所有权检查。

## 工具自身的验证

在工具工作树中运行合成仓库测试，不会运行示例研究仓库的检查：

```console
python -B -m unittest discover -s tests -p test_prepare_review.py -v
```

覆盖固定版本、脏工作树、调用者与契约、测试定位、无差异、历史失败、重命名/删除、
二进制与链接、输出边界、外部程序和导入副作用、资源限制及写入失败。
新测试按现有规则进入 core；合并前仍适用 CONTRIBUTING 的检查与独立审阅要求。
首版落实步骤见[落地计划](prepare_review_plan.zh-CN.md)。
