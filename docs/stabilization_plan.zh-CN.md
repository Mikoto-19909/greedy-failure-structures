让既有研究工具更容易维护和复现。新算法、新后端、新实例族、扩大实验规模、
展示功能和新研究实验暂时冻结，恢复开发须另行明确范围。
允许修正文档、验证现有行为、修复已确认的问题，以及经确认的局部结构整理。
不重跑已完成的正式语料或历史性能测量，不搬动原始证据与本地工作树。

审查覆盖 R2 任务计算、生产后端选择、CPU/CUDA 调度、检查点、独立验证、
分析汇总及其使用文档；并核对 R4 DUAL 的冻结源码约束和现有测试。
这是一轮静态维护审查，不是全仓库缺陷扫描或新的性能测量。

## 三个维护问题与处理顺序

### 1. 当前用法与历史阶段入口混杂：本轮整理

[R2 使用说明](../analysis/r2_usage.zh-CN.md)原先先列完整预检、定版、生产、
验证和分析流程；加速指南又将独立验证与会再次验证的 analyze 连续列出。
读者需要跨文档判断是否要重跑预检、是否需要再次核对原图。
[文档索引](README.md)还保留了只描述首轮 R4 校准的旧状态。

本轮将当前运行、恢复、仅验证与历史流程分开说明，使用现有指南互相链接；
说明 analyze 核验当前原图后重建表，单独验证适用于只检查而不重建表的场景。
保留预检及定版命令的历史用途，明确冻结证据复现必须匹配源码版本。

### 2. 生产调度与保存顺序集中在 run：下一项候选

[r2_budget_grid.py](../analysis/r2_budget_grid.py) 的 `run()` 同时处理恢复筛选、
CUDA 缓存路径、资源限制、嵌套 `save()`、后端日志、结果生成器和最终状态。
修改失败处理时，必须一起追踪工作进程返回、保存检查点、记录完成事件和关闭进程的顺序。
[r2_cuda_backend.py](../analysis/r2_cuda_backend.py) 已独立管理 GPU 拥有者；
[r2_production_backends.py](../analysis/r2_production_backends.py) 已独立选择后端，
这两层没有理由重新合并。

候选改动仅整理父进程接收结果和保存后的事件处理，保持 `run()` 签名与职责入口。
先证明这一小边界能够独立测试，再决定是否提取局部辅助函数；不引入通用后端框架。
必须保持保存检查点后才写完成事件、失败不冒充成功、累计预算、恢复复用和有界进程回收。
当前没有据此确认新的运行错误，也不宣称存在性能收益。

验收复用 [生产后端测试](../tests/test_r2_production_backends.py)中的计时/失败、
CPU spawn 与恢复、已完成 CUDA 恢复不初始化设备、预算耗尽回收场景，
以及 [R2 测试](../tests/test_r2_budget_grid.py)的配置拒绝与检查点复用。
只有实际触及 GPU 行为时，才追加已有的[真实 GPU 检查](r2_production_backends.zh-CN.md#计时恢复与检查)。

### 3. 分析计算、文件写入与绘图混在 _analyze：后续条件候选

同一 [r2_budget_grid.py](../analysis/r2_budget_grid.py) 的 `_analyze()` 串联当前原图验证、
统计调用、三张 CSV 写入和 Matplotlib 绘图。绘图布局或输出维护需阅读整条验证路径；
`--no-plot` 已提供现成的行为边界。

若第 2 项完成后仍有明确维护需求，只提取输出/绘图辅助函数，保持验证在先，
全部汇总来自同一份已验证内存数据；不调整统计公式、CSV 字段和顺序、随机抽样或状态含义。
生产与验证的统计计算继续独立。写入原子性或状态语义若另有问题，须单独复现，
不能混入纯提取并声称只是移动代码。

验收复用 `test_resume_and_independent_reconstruction`、
`test_analyze_rejects_changed_inputs_despite_old_passed_status` 和
`test_metric_denominators_and_bootstrap_unit`，比较固定小样本非计时表格，
核对无 Matplotlib 时 `--no-plot` 仍可用；触及绘图才检查现有图形输出。

## 必须保留的边界

- CLI、默认 Python 后端、种子、实例身份、有序集合、规范见证、CSV 和恢复契约保持不变。
- 生产器与独立验证器不共用求解内核或生产缓存；外观相似不足以证明可以去重。
- [DUAL CODE_PATHS](../analysis/r4_dual_io.py) 包含 `r2_design.py`、旧 R2 验证器及
  整个 `src/maxcover` 等路径。正式比较会与配置的 `code_revision` 比较源码；
  当前候选限于 `r2_budget_grid.py`，仍须复核实际依赖，不能修改冻结配置来掩盖差异。
- [快速验证适配器](r2_fast_verification.zh-CN.md)用于保留旧验证器的冻结兼容性；
  [生产后端](r2_production_backends.zh-CN.md)与验证后端的回退边界分别保留。
- 先前 benchmark、报告、验证器、生成器和记录拆分已完成；B5 已取消。
  [历史计划](README.md#implementation-plans)不自动重新启用，文件长度不作为单独拆分理由。
