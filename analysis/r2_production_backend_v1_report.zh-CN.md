# R2 首版生产后端：实现与验收

2026-09-08。源码提交 `0eda797` 实现逐图 `python/numba/cuda/auto` 生产后端。
默认 Python，NumBa 支持现有 CPU 多进程；严格 CUDA 使用一个隔离拥有者，
`auto` 只做 CPU 依赖选择。跨图批处理和自动 GPU 调度不属于首版。

## 已完成

- 真正求解、初始化、同步和回传计入每图枚举时间，未移植原型的查表计时。
- CUDA 参数、启动、同步及结果错误不能转成 CPU 成功。
- 独立复核发现的等待式关闭问题已修正，预算失败显式终止并有界回收 GPU 拥有者。
- 已完成恢复不初始化可选后端；部分恢复可在固定配置下切换后端，旧检查点不变。
- 输入、见证、计数、显存、ASCII 编译路径、执行记录及 F2 原始成本边界均有实现和检查。

完整检查运行 520 项测试，通过，4 项为明确的可选跳过；mypy 既有 38 个源码文件通过。
另用新安装的 CUDA 环境运行两项显式 GPU 检查，全部通过。独立代理的预算与真实 GPU
复测通过；真实缺依赖进程验证了自动 CPU 回退及严格后端失败。

## 本轮固定全量结果

九图先导通过后，三种执行方式各运行三次全新 1,800 图流程，覆盖 13,000 个预算结果。
验证后端统一 NumBa 四进程。计时为 `run → analyze --no-plot → summaries-only`。

- Python 四进程：完整流程中位数 **156.491 秒**。
- NumBa 四进程：**86.547 秒**，相对本轮 Python 基线减少 **44.70%**。
- CUDA 单拥有者：**119.175 秒**，相对本轮 Python 基线减少 **23.85%**。

三种方式的非计时图结果与原 R2 归档一致，同规模的三个 CSV 逐字节一致。
首版中编译 CPU 的完整流程最快；CUDA 仍串行执行 CPU 诊断，不能把内核优势直接推广到
总时间。三次观测有波动，不与前几轮的绝对时间拼接成累计倍率，也不作跨机器保证。
