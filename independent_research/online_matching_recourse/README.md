## 从实验看板使用

在算法仓库根目录启动看板，从首页或研究工作台进入“在线匹配研究”。Windows 可直接运行：

```powershell
& '.\.venv\Scripts\python.exe' run_project.py dashboard
```
页面可以查看归档结果、比较不同改派预算，并逐步回放每条请求序列。
“运行并核验”调用本目录原有实验与独立核验程序，使用固定的 6 条开发序列或 24 条比较序列。
页面中的新结果保存到仓库 `results/online_matching/`；本目录 `output/` 保留历史实验。
完整比较包含最近空位、单次腾位、预算定价链和前缀精确参照。
看板中的选择控件筛选显示内容，不改变实验协议。

Windows 下 `run.ps1` 默认使用算法仓库的 `.venv`，也可通过 `-Python` 指定解释器。
命令行 `run.py --output-root <目录>` 可指定新结果的保存位置；默认仍使用本目录的 `output/`。

## 重跑

使用已有 Python 环境。数值策略与核验只用标准库；绘图需要 Matplotlib（Python 绘图库）。本机已验证 Python 3.12.14 与 Matplotlib 3.11.2，无须安装新依赖。

在本目录运行：

```powershell
.\run.ps1
```

也可指定解释器：

```powershell
.\run.ps1 -Python '你的现有环境\Scripts\python.exe'
```

入口依次检查固定输入、运行四项手算检查、计算开发与比较结果、独立穷举核验、绘图和保存交付文件。每次创建新的 UTC 时间戳目录；UTC 是协调世界时。重跑的分步例子保存在该次结果目录。历史计算输出与当前研究报告保持不变。

只检查某个已有运行：

```powershell
python -B verify.py 'output\对应时间戳目录'
```

跨平台时分别运行 `fixtures.py`、`test_matching.py`、`run.py --split dev`、`run.py --split eval`。将两次运行打印的目录传给 `verify.py`，再运行 `analyze.py --eval 比较目录 --dev 开发目录` 和 `finalize.py 比较目录`。绘图要求 `Microsoft YaHei` 字体；缺少时应先配置字体。跨平台运行尚未实测。

## 文件用途

`matching.py` 是两个策略和前缀精确解。`fixtures.py` 生成已经固定的 30 条序列，已存在时只检查内容。`run.py` 保存逐步轨迹、指标和汇总。`verify.py` 不导入策略，改用全部单射独立验证。`analyze.py` 绘图和生成两个例子。`finalize.py` 只保存声明索引与文件指纹。

策略接口只接受当前请求前缀。预算针对同一请求整个序列，首次分配免费。所有距离使用输入坐标单位，不假设为米。本版脚本使用整数坐标；有限小数可先统一缩放为整数。数学说明中的性质适用于实数坐标，但脚本尚未实现普通小数输入。

输出中的 `summary.json` 和 `verification.json` 区分自动核验与本人审阅。`metrics.csv` 是逐序列指标，`traces.json` 是每步服务点分配与实际改派。正式包另含 `claims.csv`、`delivery_checks.json`、`artifact_hashes.json`、三张图和 `结果说明.md`。

第三方论文保存在本地 `evidence/`，已从版本收录中排除。公开来源链接在文献笔记中。本轮没有修改旧实验、安装依赖或向远程仓库发布。

## 三服务点的进一步推导

[三点一次预算的极小极大推导](报告/三点一次预算_极小极大推导.md)给出完整的第二步决策规则。目标是相对各阶段精确最优多付距离的最坏值。定理固定首步最近分配，并允许旧请求同时交换服务点；现有链式策略不能直接继承这个保证。

数学核验入口为 `python -B verify_three_point.py`，只使用标准库。它把公式与全部预算可行分配比较，每次写入新的 `output/three_point_<时间戳>/`。这项有限数学核验独立于上一轮30条固定比较，不改变原实验输入或结果。
